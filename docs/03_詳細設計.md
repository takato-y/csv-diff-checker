## FN-001 ファイルの読み込み

関連要件：REQ-002、REQ-011

### 入出力

| 区分 | 内容 |
|---|---|
| 入力 | ファイルのパス |
| 出力 | `CsvTable`（見出し・正しい行・列の数が合わない行・文字コード名） |
| 例外 | ERR-001〜ERR-004 |

### 処理

1. `CsvTableLoader.Load` が、他のアプリの書き込みを許可してファイルを読み取り専用で開き、全バイトを読む（REQ-011）
2. `EncodingDetector.Detect` が文字コードを判定する
   - BOM があれば、それに従う（UTF-8・UTF-16 LE・UTF-16 BE）
   - 不正なバイトで例外を出す UTF-8 として読めれば UTF-8 とする
   - 不正なバイトで例外を出す Shift_JIS として読めれば Shift_JIS とする
   - どちらでも読めなければ ERR-003
3. `CsvParser.Parse` が RFC 4180 に沿って文字列をレコードに分ける
   - 引用符内のカンマ・改行・`""` を値として扱う
   - 空行は読み飛ばす。行番号は数え続ける
   - 引用符が閉じていなければ ERR-002
4. `CsvTable.FromText` が1件目を見出しにする。空の見出しには「（列n）」を付け、重複は ERR-004
5. 列の数が見出しと合わない行は、行番号・理由・値とともに `Problems` に入れ、比較に使う行から外す

## FN-002 差分の判定

関連要件：REQ-003、REQ-004、REQ-005、REQ-006

### 入出力

| 区分 | 内容 |
|---|---|
| 入力 | 旧・新の `CsvTable`、`DiffOptions`（照合する列、値の前後の空白を無視するか） |
| 出力 | `DiffResult`（比較した列・片方にしかない列・差分・確認が必要な行・一致の件数） |
| 例外 | ERR-005（`ArgumentException`） |

### 処理

1. 照合する列が未指定、またはどちらかの表に無ければ ERR-005
2. 両方にある列を「比較した列」、片方にしかない列をそれぞれ一覧にする（REQ-006）
3. 旧・新それぞれで、照合する値（前後の空白を除いた値の組み合わせ）ごとに行を集める
   - 照合する値がすべて空の行は、確認が必要な行にする
   - 同じ照合する値の行が複数あれば、すべての行を確認が必要な行にし、その値を比較から外す
4. 列の数が合わない行から照合する値の候補を取り、相手側でも比較から外す（REQ-005）
   - 候補は、先頭から数えた位置と末尾から数えた位置の2つ。どちらの列がずれたか分からないため
   - 候補が取れない行は、相手側の行が誤って追加・削除と出ている可能性を確認が必要な行に書く
5. 新ファイルの順に、旧ファイルに無い値を「追加」、ある値は比較した列（照合する列を除く）を比べる
   - 比べる前に改行コードを LF にそろえ、設定に応じて前後の空白を除く
   - 違いがあれば「変更」とし、列ごとに変更前・変更後を持つ。無ければ一致の件数に数える
6. 旧ファイルの順に、新ファイルに無い値を「削除」とする
7. 差分は変更・追加・削除の順に並べる

## FN-003 結果の保存

関連要件：REQ-007、REQ-011、REQ-012

### 入出力

| 区分 | 内容 |
|---|---|
| 入力 | `DiffResult`、保存先のパス |
| 出力 | 比較結果の CSV、確認が必要な行の CSV（`（ファイル名）_要確認.csv`） |
| 例外 | ERR-007、ERR-008（`IOException`・`UnauthorizedAccessException`） |

### 処理

1. 表の形は `DiffTableFormat` で作る。画面の表と同じ列（差分・照合する値・旧ファイルの行・新ファイルの行・変更した列・比較した列）とする
2. 変更したセルは「変更前 → 変更後」とする
3. 各値は `CsvText.Neutralize` で無害化し、`CsvText.Escape` で必要なときだけ引用符で囲む（REQ-012）
4. UTF-8（BOM付き）・改行 CRLF で、同じフォルダの一時ファイルに書き、書き終えたら置き換える（REQ-011）

## FN-004 画面の操作の制御

関連要件：REQ-001、REQ-003、REQ-007、REQ-008、REQ-009、REQ-010、REQ-011、REQ-013、REQ-015

### 状態

`ComparisonState` が持つ。

| 項目 | 内容 |
|---|---|
| `OldFile`・`NewFile` | 読み込んだファイル（パスと表）。未読み込み・読み込み失敗は null |
| `SelectedKeys` | 選んでいる照合する列（共通の列の並び順） |
| `TrimValues` | 値の前後の空白を無視するか（初期値は true） |
| `Result` | 比較結果。設定やファイルが変わったら null に戻す |
| `IsBusy` | 処理中かどうか |

### 処理中の排他

1. `RunExclusiveAsync` は、`IsBusy` が true なら何もせずに戻る
2. `IsBusy` を true にして、`SetCommandState` で入力とボタンをすべて無効にする
3. 処理を実行する。重い処理（読み込み・比較）は別スレッドで実行する（REQ-013）
4. 例外の有無にかかわらず、`IsBusy` を false に戻し、操作の可否を計算し直す

`StartAsync`・`BrowseAsync`・`LoadFileAsync`・`DropOnFileAsync`・`DropFilesAsync`・`SwapAsync`・`CompareAsync`・`SaveAsync` はすべて `RunExclusiveAsync` を通す。
`ChangeKeys`・`ChangeTrim` は処理中なら変更を受け付けず、画面の表示を状態に戻す（`SetKeyCandidates`・`SetTrimValues`）。

### 主な操作

| 操作 | 処理 |
|---|---|
| 読み込み | 読み込めたら状態とファイル欄を更新する。失敗したら（例外の種類を問わず）その側を null に戻し、警告を出す（ERR-001〜ERR-004）。どちらの場合も前の結果を消し、照合する列の候補を作り直す |
| 照合する列の候補 | 両方にある列を候補にする。選んでいた列のうち候補に残る列を引き継ぎ、無ければ先頭の列を選ぶ |
| ファイル欄へのドロップ | 存在するファイルがちょうど1つのときだけ、その欄に読み込む |
| 画面へのドロップ | 存在するファイルが1つなら、旧ファイルが未読み込みのときは旧、読み込み済みなら新に読み込む（両方読み込み済みなら新ファイルを置き換える）。2つ以上なら先頭の2つを旧・新の順に読み、両方読めたときだけ割り当てをステータス欄に出す |
| 入れ替え | 読み込み済みの2つのファイルをメモリ上で交換する。ファイルは読み直さない。照合する列の候補は両方にある列のまま変わらないため、選択はそのまま引き継ぐ（REQ-009） |
| 照合する列・空白の設定の変更 | 変更が無ければ何もしない。変更があれば前の結果を消し、比較し直すよう示す（REQ-008） |
| 比較 | 比較結果と要約（`ResultSummary`）を画面に渡す。ERR-005 は警告にする |
| 保存 | 下の手順 |

### 保存の手順

1. 結果が無ければ何もしない。保存先を利用者に選ばせ、取り消したら何もしない
2. 保存先と、確認が必要な行の保存先（確認が必要な行がある場合）が入力ファイルと同じなら ERR-006
3. 確認が必要な行の保存先が既にあれば、上書きしてよいか確かめる。「いいえ」なら何もしない
4. 比較結果を書く。失敗したら ERR-007
5. 確認が必要な行が無い場合、古い確認が必要な行のファイルが残っていれば知らせて終える
6. 確認が必要な行を書く。失敗したら ERR-008

## FN-005 起動引数の解釈

関連要件：REQ-010

1. 引数を先頭から1つずつ読む
2. `--old`・`--new`・`--key`（大文字・小文字は区別しない）の後ろの値を取る。値が無い場合と、次の要素が `--` で始まる場合は「値なし」として無視し、次の要素は引数名として読む
3. 知らない引数は読み飛ばす。後ろの引数の解釈はずれない
4. `--key` はカンマで区切り、前後の空白を除く。同じ列は1つにまとめる
