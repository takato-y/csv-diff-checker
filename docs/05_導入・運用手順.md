## 1. 導入

### 1.1 必要なもの

| 項目 | 内容 |
|---|---|
| パソコン | Windows（64bit） |
| 実行環境 | .NET 10 Desktop Runtime（x64）。配布用の EXE には含めていない（REQ-014） |
| 配布物 | `CsvDiffChecker.exe`（1ファイル）。GitHub の Release に添付している |
| 管理者権限 | EXE の実行には不要。.NET Desktop Runtime のインストールには必要になる場合がある |

### 1.2 配置

1. .NET 10 Desktop Runtime（x64）をインストールする。入手先は README の「動作環境」に示す
2. `CsvDiffChecker.exe` を、利用者が書き込めるフォルダ（例：ドキュメントの下に作ったフォルダ）に置く
3. デスクトップなどにショートカットを作る（任意）

EXE は設定ファイルやデータを作らない。配置したフォルダには EXE だけがあればよい。

### 1.3 動作確認

1. `CsvDiffChecker.exe` を起動する
2. リポジトリの `samples` にある `products_old.csv` を「旧ファイル（比較元）」、`products_new.csv` を「新ファイル（比較先）」に指定する
3. 「照合する列」で「商品コード」を選び、「比較する」を押す
4. 件数が「変更 3件　追加 2件　削除 1件　一致 5件」、確認が必要な行が3行になれば正常である（README の「サンプルで試す」と同じ結果）

### 1.4 自社のデータで使う

- 比べる2つのファイルは、どちらも1行目が見出しの CSV にする（REQ-002 の前提）
- 照合する列には、行ごとに違う値が入る列（商品コード・社員番号など）を選ぶ
- 業務システムから書き出したファイルは、書き出したまま使える。Excel で開いて保存し直す必要はない

## 2. 日々の使い方

1. 旧ファイルと新ファイルを、「参照…」ボタンかドラッグ＆ドロップで指定する
2. 「照合する列」を選び、必要に応じて「値の前後の空白を無視する」を切り替える
3. 「比較する」を押し、件数と一覧を確かめる
4. 「確認が必要な行」タブに件数があれば、元のファイルの該当する行を確かめる
5. 記録が要る場合は「結果をCSVに保存（全件）…」で保存する。確認が必要な行がある場合は「（ファイル名）_要確認.csv」も保存される

設定（照合する列・空白の扱い）を変えると、前の結果は消える。変えた後は、もう一度「比較する」を押す。

## 3. 困ったとき

エラーのメッセージが出た場合や、結果が想定と違う場合は、[障害対応手順書](06_障害対応手順書.md) で該当する節を探す。

| よくある症状 | 見る節 |
|---|---|
| ファイルを読み込めない | 障害対応手順書 4章 ERR-001〜ERR-004 |
| 「比較する」が押せない | 障害対応手順書 5.2 |
| 保存できない | 障害対応手順書 4章 ERR-006〜ERR-008 |
| 結果が想定と違う | 障害対応手順書 5.3・5.4 |

## 4. 保守

### 4.1 ソースの構成

構成と各クラスの責任は [基本設計書](02_基本設計.md) の2章に示す。部品の組み立ては `src/CsvDiffChecker.App/Program.cs` の1か所にある。

### 4.2 変更後の確認

変更したら、次をすべて行う。

| 順 | 確認 | コマンド・方法 | 合格の条件 |
|---|---|---|---|
| 1 | ビルド | `dotnet build CsvDiffChecker.slnx -c Release` | 警告 0・エラー 0 |
| 2 | 自動テスト | `dotnet test CsvDiffChecker.slnx -c Release` | 全件合格 |
| 3 | テスト仕様書の一覧 | `python scripts/update_test_spec.py --check` | 「最新です」と出る。テストを足した場合は `--check` を付けずに実行して作り直す |
| 4 | 設計書と障害対応手順書の突き合わせ | `python scripts/check_docs_trace.py` | 「PASS」と出る |
| 5 | 画面 | 配布用 EXE を作り（`scripts/publish.ps1`）、サンプルで起動する | [テスト仕様書](04_テスト仕様書.md) 3章の項目がすべて満たされる |

1〜4 は、main への push とプルリクエストのたびに GitHub Actions でも実行される。5 は手元の環境で行う。

### 4.3 よくある変更

| 変更 | 直す場所 | 確認で特に見ること |
|---|---|---|
| 突き合わせの決まり（空白・改行の扱いなど） | `CsvDiffEngine` | FN-002 のテスト、サンプルのテスト |
| 読み込める文字コードを増やす | `EncodingDetector` | FN-001 の文字コードのテスト。誤判定が増えないこと |
| 結果の列の並び | `DiffTableFormat` | 画面の表と保存する CSV の両方（同じ形を使っている） |
| 画面の文言・配置 | `MainForm`（表示）、`MainPresenter`（メッセージの文） | 画面の確認（4.2 の 5） |
| 部品の差し替え（例：Excel ファイルの読み込み） | `ICsvTableLoader` などを実装したクラスを作り、`Program` で差し替える | Presenter のテストはそのまま使える |

### 4.4 .NET の更新

- .NET の修正版（セキュリティ修正を含む）は、利用者のパソコンの .NET 10 Desktop Runtime を更新して取り込む。EXE は作り直さなくてよい（実行環境を EXE に含めていないため）
- 開発環境の SDK は `global.json` で 10.0.404 以上の .NET 10 に固定している
- .NET 10 のサポートは 2028-11-14 に終わる。それまでに次の LTS 版へ移す。手順は、各 csproj の対象（`net10.0`・`net10.0-windows`）と `global.json`・CI の SDK の版を上げ、4.2 の確認をすべて行うことである

## 5. 運用管理

### 5.1 定期点検

| 頻度 | 点検 | 方法 |
|---|---|---|
| 月1回 | 利用者のパソコンの .NET 10 Desktop Runtime が最新の修正版か | PowerShell で `dotnet --list-runtimes` を実行し、`Microsoft.WindowsDesktop.App 10.0.x` の版を確かめる |
| 版を出すとき | 4.2 の確認がすべて合格しているか | GitHub Actions の結果と、手元の画面の確認 |
| 年1回 | .NET 10 のサポート終了（2028-11-14）までの残り期間 | 4.4 の計画を立てる |

### 5.2 バックアップと戻し方

- このツールはデータを持たない。入力は利用者の元のファイルで、ツールは変更しない（REQ-011）。出力は利用者が保存先を選んだ CSV である。ツールとしてバックアップするものは無い
- 新しい版で不具合が出た場合は、GitHub の Release から前の版の EXE を取得して置き換える。設定ファイルが無いため、置き換えるだけで戻る

### 5.3 資格情報・鍵・トークン

使わない。ネットワークにも接続しない。

### 5.4 連絡体制

| 役割 | 受け持つこと |
|---|---|
| 利用者 | ツールを使う。エラーのメッセージや想定と違う結果に気づいたら、運用担当者へ伝える |
| 運用担当者 | 障害対応手順書に沿って切り分け・対処する。直らなければ保守担当者へ連絡する |
| 保守担当者 | 原因を調べ、必要ならソースを直して新しい版を出す |

連絡するときは、障害対応手順書 6章の項目をそろえる。
