## 1. 目的と背景

業務では、商品マスタや社員名簿などのリストを定期的に新しい版へ更新する。
更新のたびに、担当者は新旧のリストを並べて、増えた行・なくなった行・変わった項目を目で確かめている。
この作業は見落としが起きやすく、並び順が違うと手間が大きく増える。

本システムは、2つのリスト（CSV ファイル）を比べ、変更点を一覧にする Windows デスクトップアプリである。
目的は、見比べる作業の時間を減らし、変更点の見落としをなくすことである。

## 2. 対象の業務と利用者

| 項目 | 内容 |
|---|---|
| 利用者 | マスタやリストを更新・確認する事務担当者 |
| 対象の業務 | マスタの更新内容の確認、システム移行前後の照合、取引先から届くデータの受け入れ確認 |
| 扱うデータ | 業務システムや Excel から書き出した CSV ファイル（1行目が見出し） |

## 3. 機能要件

| ID | 要件 | 補足 |
|---|---|---|
| REQ-001 | 比べる2つのファイル（旧ファイル・新ファイル）を、参照ボタンかドラッグ＆ドロップで指定できる | 手入力は受け付けない。表示中のファイルと結果の食い違いを防ぐため |
| REQ-002 | ファイルの文字コードを自動で判定して読み込む | 対象は Shift_JIS・UTF-8（BOM の有無）・UTF-16（BOM付き）。どれとしても読めないファイルは読み込まない |
| REQ-003 | 利用者が選んだ列（照合する列）の値で、新旧の行どうしを突き合わせる | 1列以上を選ぶ。複数列を選んだ場合は組み合わせで突き合わせる。行の並び順には依存しない |
| REQ-004 | 突き合わせた結果を「追加」「削除」「変更」「一致」に分け、件数と一覧を示す | 変更した項目は「変更前 → 変更後」で示す |
| REQ-005 | 正しく突き合わせられない行を「確認が必要な行」として一覧にし、比較から外す | 対象は照合する値の重複・空・列の数の不一致。相手側のファイルの同じ値の行も外し、誤った「追加」「削除」を出さない |
| REQ-006 | 片方のファイルにしかない列を一覧にする | その列は比較しない |
| REQ-007 | 比較結果を CSV ファイルに保存できる | Excel でそのまま開ける形式とする。確認が必要な行がある場合は別のファイルにも保存する |
| REQ-008 | 設定の変更や処理の途中の操作によって、表示中のファイルと結果が食い違わない | 設定を変えたら前の結果を消す。処理中は他の操作を受け付けない |
| REQ-009 | 旧ファイルと新ファイルを入れ替えられる | 選んでいた照合する列は引き継ぐ |
| REQ-010 | 起動時の引数でファイルと照合する列を指定できる | 指定がそろっていれば、起動後にそのまま比較する |

## 4. 非機能要件

| ID | 要件 | 補足 |
|---|---|---|
| REQ-011 | 元のファイルを変更しない。結果の保存で入力ファイルを上書きしない | 保存に失敗しても中途半端なファイルを残さない |
| REQ-012 | 保存した CSV を表計算ソフトで開いても、値が数式として動かない | `=` `+` `-` `@` で始まる値は無害化する。数値はそのまま残す |
| REQ-013 | 読み込みと比較の間も画面が固まらない | 重い処理は画面の処理と別に実行する |
| REQ-014 | 動作環境は Windows（64bit）と .NET 10 Desktop Runtime とする | EXE は1ファイルにまとめ、実行環境は利用者の PC 側に置く |
| REQ-015 | 比較の処理と画面の操作の流れを、画面を操作せずに自動テストで確かめられる構造にする | 画面と処理を分け、部品はインターフェースで差し替えられるようにする |

## 5. 対象外

- Excel ファイル（xlsx）の直接の読み込み
- BOM のない UTF-16 の判定
- 大文字と小文字、全角と半角を同じ値として扱う比較
- 3つ以上のファイルの比較
- 結果の印刷

## 6. 前提

- 比べる2つのファイルは、どちらも1行目が見出しである
- 照合する列には、行ごとに異なる値（商品コード・社員番号など）が入っている
