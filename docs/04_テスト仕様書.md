## 1. 方針

- すべてのテストは自動テスト（xUnit）で実行する。`dotnet test CsvDiffChecker.slnx -c Release` で全件を実行できる
- FN-001〜FN-003・FN-005 は部品を直接呼んで確かめる。ファイルの読み書きを伴うテストは、テストごとに作る一時フォルダで行う
- FN-004（画面の操作の流れ）は、画面の代わりに `FakeView` を、部品の代わりに `FakeLoader`・`FakeWriter` を渡して確かめる。画面を操作せずに、操作の可否・処理中の排他・保存の守りを検査する（REQ-015）
- 「件数」は、同じテストを異なるデータで実行する回数（xUnit の `InlineData`）である
- テストのデータはすべて架空のものである

## 2. テストケース

一覧はテストコードのクラス名とメソッド名から `scripts/update_test_spec.py` で作る（手で直さない）。「確認すること」はメソッド名の区切りを読点に置き換えたものである。
テストを足すと、後ろのテストケースの番号がずれる。番号は版ごとの一覧の中での番号として扱い、テストの特定にはメソッド名を使う。

一覧には結果を書かない（固定の「合格」を書くと、テストが失敗しても一覧が合格のままになるため）。結果は `dotnet test` の出力か、CI の実行記録で確かめる。

## 3. 画面で確かめたこと

自動テストの対象外である画面の見た目は、配布用の EXE をサンプルのファイルで起動し、画面を画像に撮って確かめた（2026-11-19）。

| 確かめたこと | 結果 |
|---|---|
| 比較結果の表示（変更・追加・削除の色分け、「変更前 → 変更後」の表示） | 合格 |
| 「確認が必要な行」タブの表示 | 合格 |
| 「値の前後の空白を無視する」を変えたときに前の結果が消え、保存ボタンが押せなくなる | 合格 |
| 照合する列の説明やファイル欄の文字が切れない | 合格 |
| ファイル欄が読み取り専用で、手入力できない（`MainForm` の `ReadOnly`。自動テストの対象外） | 合格 |
